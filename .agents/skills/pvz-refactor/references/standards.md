# 重构质量标准

用于候选排序、方案比较和实施后的审查。每次只检查与目标有关的维度；不以模式数量、文件数量或统一行数阈值打分。

| 标准 | 合格证据 | 常见失败 |
| --- | --- | --- |
| 有具体收益 | 能说明“修改同一规则涉及更少的业务位置”或“调用者只需要理解一个明确接口”等前后差异。 | 只说更优雅、文件太长或应该套用某个模式。 |
| 行为与契约保持 | 核对参数、返回值、异常、默认值、副作用、事件次数与顺序，以及场景/数据消费者。 | 签名看似不变，但改变了目标过滤、随机抽取、初始化或动画触发时机。 |
| 职责归属清楚 | 清楚说明模块拥有的状态、隐藏的实现与对外操作；遵循现有服务/组件边界。 | 业务逻辑堆入 Global、GlobalUtils，或在多个组件重复维护同一份状态。 |
| 依赖更容易追踪 | 依赖方向与调用者明确；事件有确定的发送者、消费者和生命周期。 | 为“解耦”把局部调用全部改成字符串事件，或新增只有转发功能的空层。 |
| 抽象成本合理 | 抽取重复的是同一业务知识，或隔离的是会独立变化的职责；调用方式仍直观。 | 因代码形状相似而合并不同玩法，或为单一实现添加工厂、接口和容器。 |
| 资源与持久化兼容 | 节点绑定、动画、UID、导出覆盖、字典键、枚举值和关卡标识均有核对记录。 | 只查 GDScript 引用，就断言回调无用或字段可改名。 |
| 生命周期可靠 | 初始化、切换、暂停、取消、死亡和退出有明确所有者；不会重复推进或重复释放。 | 将正常死亡替换为裸 queue_free，或让父状态机和子状态机同时更新。 |
| 改动可审阅 | 每批目标清楚，差异与候选一致，能够指出新增的复杂度及其理由。 | 混入功能、调参、素材更新、全文件格式化或用户改动整理。 |
| 结论与证据一致 | 区分差异核查、资源引用核查、语法检查、运行验收和性能测量。 | 未运行游戏却说完全兼容；没有测量却声称更快。 |

## GDScript 与项目编码约定

以当前 AGENTS.md 为准，以下只列重构时容易遗漏的要求：

- 类说明放在脚本头部。类、成员、常量、信号、枚举及函数使用 `##` 文档注释；成员注释紧贴声明或其注解之前。
- 所有变量与常量都说明用途，包括成员、导出、局部、循环变量及 lambda 参数；函数内部使用 `#`，必要时在行尾简述。
- 在函数文档中用 `[param 参数名]` 说明每个参数，注明有意义的返回值、副作用、边界及特殊值。
- 涉及时间、位置、ID、范围和生命周期时说明单位、坐标空间及约定，不只翻译标识符。
- 使用 `[member]`、`[method]`、`[code]`、`[br]` 等 Godot 文档标记；优先沿用已有类型与命名，不能借类型调整改变空值语义。
- 只修正本批相关的缺失或失效注释，不以补注释为由重写整个旧文件。

## 讨论与候选示例

假设用户说：“同一块攻击区域被多个博士技能重复计算，帮我重构。”

先检查技能与 `ZB001DoctorCellQuery` 的调用，核对行列坐标、边界过滤、目标选择时刻以及动画关键帧。若确实是同一格子查询规则，可让现有查询工具拥有纯查询，各技能继续拥有随机选择、锁定目标和释放效果。若各技能在不同阶段选取目标，则保留差异，不合并为一个覆盖所有玩法的接口。

验收应是“各技能使用同一查询规则，原有选择时刻与攻击效果保持”，而非“脚本少了若干行”。这只是分析方式示例，不宣称当前代码存在该问题。

以下用于说明编写依据，不要求未来使用者在线加载或安装这些仓库：

- [reviewing-code-modularity-skill](https://github.com/tyshkovskii/reviewing-code-modularity-skill/blob/main/SKILL.md)：借鉴审查/设计/实施模式、模块拥有/隐藏/公开的边界，以及最小有效调整。作为主要思路来源。
- [thoreinstein/agents 的 refactor](https://github.com/thoreinstein/agents/blob/main/skills/refactor/SKILL.md)：借鉴影响范围、风险和依赖顺序；其“仅分析”限制只用于本 skill 的审查模式。
- [awesome-copilot 的 refactor](https://github.com/github/awesome-copilot/blob/main/skills/refactor/SKILL.md)：借鉴保留行为、小步抽取、重复规则与条件简化；示例需自行核对等价性，不直接套用 JS/TS 的模式和行数阈值。
- [haxqer/godot-skill](https://github.com/haxqer/godot-skill/blob/main/skill/godot/SKILL.md)：借鉴场景、资源、UID 与架构边界一起审查的思路；不引入它的 Python 工具链或默认运行流程。

没有照搬默认补测试、频繁运行测试、自动提交或强制工作树流程。验证、注释、权限和修改范围以本项目约定及用户当前授权为准。Star 只反映仓库关注度，不作为技能质量结论。
