# 验证与交付

## 默认检查

遵循当前 AGENTS.md：不新增测试，不运行测试。已有测试如果因本批重命名失效，仅同步其引用，不扩展测试范围。

默认可做只读文件与差异检查；不要自动启动游戏、执行测试脚本或用用户存档试运行。没有测试不等于不能做局部可审阅重构，但无法确认的行为契约需要讨论，不能声称运行等价。

### 建立基线

在项目根使用已有工具读取状态和目标差异；有 staged 与 unstaged 改动时分别查看。新建、未跟踪文件不会自动出现在普通 git diff 中，应单独读取并检查。

~~~powershell
git status --short
git diff --name-status
git diff --cached --name-status
git diff --check
git diff --cached --check
~~~

检查命令必须按目标范围收敛；上述完整状态检查用于辨认基线，不能据其结果归责本次重构。git diff --check 只检查空白等差异问题，不证明语法、绑定或玩法正确。

### 沿契约搜索

先用 rg --files 发现实际目录，优先精确文字查询。脚本符号没有命中不代表无调用，继续检查动画方法名、序列化键和运行时约定。

例如核查 _shoot_bullet 的全部文本消费者：

~~~powershell
rg -n -F -- '_shoot_bullet' scripts scenes animation resources
~~~

按改动选择检查项：

| 改动 | 必需的核对 |
| --- | --- |
| 抽取函数/移动职责 | 原调用者、参数、返回值、副作用、边界和执行顺序；新增模块的状态所有者。 |
| 函数/信号重命名 | .gd 调用、字符串 Callable/call、EventBus、.tscn 的 connection、.tscn/.tres 的方法轨道。 |
| 节点/脚本/资源搬迁 | 搬迁映射、配套 .gd.uid、path 与 uid、owner、% 唯一名称、NodePath、继承覆盖和导出绑定。 |
| 枚举/配置/存档调整 | 旧数字/键/字段/默认值、加载与保存两端、嵌套字典、旧资源消费者、关卡 ID。 |
| 组件/状态机/计时抽取 | 初始化注入、单一驱动、暂停与冻结、取消/退出、重复信号、已释放目标和时间单位。 |
| 目标选择/格子查询 | 行列边界、地形、阵营、受击状态、采样时刻、权重与随机调用顺序；不能把玩法变化混作重构。 |

手工检查修改后的每个文件，确认没有意外格式化、元数据更新、无关资源改动或用户内容丢失。对被修改的既有用户文件，比较任务开始的内容与最终内容，不只比较 HEAD。

## 用户明确要求运行验证时

授权按类型和范围解释：语法检查、启动检查、游戏场景验收、存档兼容检查和性能测量并不互相替代。已有明确授权不重复询问；不要擅自新增测试来满足默认流程。

1. 只读发现现有 Godot 可执行文件、项目版本和素材条件；依据其帮助与项目已有验证方式选择命令。找不到工具时说明限制，不自动安装引擎、插件或测试框架。
2. 优先隔离副作用。游戏启动可能进入用户加载/自动保存流程；存档验收使用经授权的副本或临时用户，不能覆盖真实数据。编辑器导入也可能生成 .godot 缓存与资源元数据，应事先考虑工作区影响。
3. 仅验收受影响的路径，并保留运行环境、命令、退出状态和有意义的日志。没有新增变化或失败理由时，不反复扩大检查范围。
4. 关卡/战斗可按影响选择：初始化与切换；前院/泳池/屋顶；正常/展示/花园；暂停/倍速/冻结；目标消失与角色死亡；状态切换与动画事件；博士受击和奖杯流程。
5. 存档兼容需比较读取旧数据、缺省字段及保存后再读取的语义；性能需同场景、相同条件与可比较测量。静态阅读、成功启动或主观观感不能替代这些证据。

如果引入 Python 辅助工具，先按当前用户环境约定选择环境；本 skill 不默认依赖 Python，也不提供未经项目核验的自动测试命令。

## 最终报告

报告包括实际变更、结构收益、影响文件与保持项、执行过的检查及结果、未执行的验证与剩余风险。审查模式报告建议，不能写成已实施。

可用的结论表述：

- “目标范围的差异与文本引用已检查，未运行测试；运行时行为待场景验收。”
- “已按授权执行某项语法/启动检查，结果为……；这不覆盖其余游戏模式。”

不要使用“全部测试通过”“完全兼容”或“性能优化成功”，除非有相应范围的实际证据。完成后判断 AGENTS.md 是否需要更新；没有用户同意时只提出具体建议，不修改文件。
