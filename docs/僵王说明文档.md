# 僵王说明文档

本文说明僵王基类、当前僵王博士的结构、技能、场景配置，以及关卡、卡牌、胜利和存档接入。代码基准为 `main` 分支的 `485ffe8`，依据源码、场景和资源整理；文中的时间与数值是配置值，不是运行实测结果。

当前注册的僵王只有 `CharacterRegistry.ZombieBossType.ZB001Doctor = 1`，`Null = 0` 表示未配置。僵王直接继承通用角色基类，通过独立管理集合参与敌方计数，不加入普通僵尸行列表。

## 2. 僵王基类 `ZB000Base`

### 2.1 共用组件与信号

基类沿用通用角色的 `%Body`、`%HurtBoxComponent`、`%HpComponent`、`%AnimComponent` 和 `%Shadow`。基础场景的 `HurtBoxDetection` 使用第 3 层 `ZombieHurtBoxDetection`，`HurtBoxReal` 使用第 10 层 `ZombieHurtBoxReal`。

| 接口 | 含义 |
| --- | --- |
| `signal_character_death()` | 继承的逻辑死亡通知，管理器据此扣敌方数量和累计击杀 |
| `signal_update_speed(speed_factor_product)` | 继承的角色速度变化通知，动画和动作计时使用该倍率 |
| `signal_trophy_requested(global_pos)` | 死亡演出或直接消失请求奖励，参数为世界坐标；基类不直接生成奖杯 |
| `signal_status_update` | 通知检测器重新索敌；具体僵王在状态进入完成或受击开关改变后发送 |
| `trophy_spawn_point` | 可选的唯一命名 `%TrophySpawnPoint`，奖励请求优先采用该点的世界位置；基类缺失时回退到根位置 |

`signal_status_update` 在基类只声明，由博士及其状态机发送，检测组件监听。局部 `unused_signal` 注解用于这种跨脚本接口声明。

### 2.2 受击资格与植物交互

`_can_receive_damage()` 仅在角色未死亡、初始化类型为 `IsNorm`、仍在树中且未排队删除、受击组件有效并启用时返回 `true`。普通子弹伤害、完全冰冻和火爆辣椒共用这个检查，避免旧碰撞结果或延迟动画调用绕过受击窗口。

检测组件对僵王不执行普通角色的同行限制，仍要求实际检测范围重叠、受击组件启用，以及攻击状态掩码包含 `IsNorm`。跨行可攻击范围由几何区域决定，不能据此理解为所有植物都能全场攻击。

| 方法或交互 | 当前规则 |
| --- | --- |
| `be_attacked_bullet(...)` | 通过受击资格后调用通用角色伤害入口，致死由 HP 组件触发死亡 |
| `be_ice_freeze(time, new_time_ice_end_decelerate)` | 受击窗口内先扣除通用冻结伤害 `20`，再施加冻结及后续减速；若致死，父类返回后再次清理冻结表现 |
| `be_ice_decelerate(time)` | 存活时沿用通用减速；死亡后不再创建减速计时或染色 |
| `be_jalapeno(attack_value)` | 受击窗口内先解除冻结与减速，再结算穿透伤害，保留僵王死亡流程 |
| 寒冰菇与火爆辣椒 | 管理器遍历每只存活僵王；任意行辣椒都可请求攻击，各实例仍检查自身受击窗口 |
| 大嘴花 | 对僵王调用伤害接口，不套用普通僵尸吞食删除流程 |
| 缠绕海草 | 对僵王只结算专用伤害并消耗海草，不拖动机甲入水 |
| 地刺与地刺王 | 可以通过共用受击入口伤害僵王，植物自身被碾压的处理独立 |
| 窝瓜检测 | 沿用僵王受击开关和跨行判断，不使用撑杆或海豚落点规则 |

上述共用检查约束这些正常攻击入口；强制死亡、直接改 HP 或节点删除属于不同生命周期操作。

### 2.3 三种退场方式

| 操作 | 击杀计数 | 奖杯请求 | 表现 |
| --- | --- | --- | --- |
| 正常致死伤害 / `character_death()` | 逻辑死亡通知由管理器累计一次 | 具体死亡动画调用 `request_trophy()` | 博士进入死亡状态机 |
| `character_death_disappear()` | 通过 `Hp_loss_death(false)` 登记死亡；已死亡时不重复扣血或计数 | 在 `queue_free()` 前立即请求 | 跳过余下死亡演出并释放 |
| 仅 `queue_free()` / 离树清场 | 移除存活计数，不增加击杀数 | 不请求 | 直接清理节点 |

`character_death()` 先调用通用逻辑死亡，发出死亡信号，再以 `Death` 原因禁用受击并整理死亡动画速度。重复调用不重复发死亡通知。博士子类随后提交 `request_death()`，不依赖可被取消的亡语启动演出。

`request_trophy()` 只接受已死亡的正常出战实例，且角色必须仍在树中、未排队删除。它可以发出请求，但是否获胜、是否允许生成奖杯及重复请求防护由管理器处理。

### 2.4 死亡时的控制效果与速度

`prepare_death_animation()` 停止已有冻结、减速和黄油等控制计时器，释放冰块并恢复冰冻颜色；速度因素只保留初始随机倍率。初始倍率非法或不大于零时回退为 `1`，保证死亡演出能够继续。

死亡后 `update_speed_factor()` 和 `be_ice_decelerate()` 不再接受新的控制更新，旧计时回调不会重置死亡速度。`_fade_and_remove()` 防止重复启动，在 1 游戏秒内淡出后释放；场景暂停和全局时间倍率仍影响该 Tween。

## 3. 当前博士的初始化与场景结构

### 3.1 初始化类型

| 类型 | 博士行为 |
| --- | --- |
| `IsNorm` | 先关闭受击、选择场地资源并连接状态和死亡表现通知；通用角色排队初始化随机速度后，再延迟初始化、启动专用状态机 |
| `IsShow` | 禁用战斗受击，机甲循环 `Zombie_boss_head_idle`、驾驶员循环 `Zombie_Boss_driver_idle`，不启动战斗状态机 |
| `IsGarden` | 沿用通用花园初始化；博士未提供专用花园玩法或技能启动流程 |

角色应由管理器创建，入树前完成正常初始化类型、位置、登记和信号连接。这样 `_ready()` 期间的通知不会遗漏，恢复血量也能在延迟状态机启动前完成。

### 3.2 关键节点

博士场景包含机甲 `AnimationPlayer`、驾驶员独立播放器、唯一命名 `%StateMachine`、`AnimationController`、`Skills`、`PartMotions`、`%HpStageChangeComponent`、根节点 `DeathRemainTimer` 和 `%TrophySpawnPoint`。死亡表现另依赖 `Dying/DeathExplosionIntervalTimer` 和直属根节点的 `DeathExplosionEffects`，后者继承角色整体淡出。

主状态机必须绑定角色、机甲播放器、入场状态、Idle、五个完整技能状态、Dying、Dead 和动画控制器。复合技能分别绑定实际效果节点与子状态机。技能通过导出引用访问标记点和部件，不从角色名称推断绑定。

根节点职责还包括：每次入场重置落脚去重记录；动画方法轨道播放落脚声音和镜头震动；检查当前动画名，拒绝动作切换后到达的旧音效调用。展示实例不播放这些战斗音效。

### 3.3 当前主要参数

| 参数 | 脚本默认 / 当前场景值 | 说明 |
| --- | --- | --- |
| `HpComponent.max_hp` | 当前场景 `90000` | 使用普通 HP 组件；运行时生命不保存在注册表 |
| `HpStageChangeComponent.boundary_value_hp` | 当前场景 `[20000, 10000, 0]` | 前两阶段更换脚、头、下颌、手部破损贴图，末阶段保留最终外观 |
| `random_speed_range` | 继承默认 `(0.9, 1.1)` | 正常实例初始化随机速度；我是僵尸模式由通用初始化改为 `(1, 1)` |
| `idle_duration` | 默认 `2`，场景 `3` 动作秒 | 到期后还需等当前待机动画周期结束，并非精确每 3 秒释放技能 |
| `initial_skill_sequence` | 默认空，场景 `Spawn × 3` | 开场优先执行三轮完整放置技能，不是只放三只僵尸 |
| `max_rounds_without_head_skill` | `5` | 连续五个非吐球技能回合后，下次选择强制吐球 |
| `death_animation_speed_scale` | 默认 `2`，场景 `1.5` | 乘初始随机倍率；影响死亡前抬头、机甲及驾驶员死亡动作 |
| `death_remain_duration` | `10` 游戏秒 | 最终举旗循环后保留；不乘死亡动画倍率，之后另有 1 秒淡出 |
| 低头待机切动作过渡 | 默认 `0.15`，场景 `0.05` 动作秒 | 从低头待机切吐球或抬头时捕获当前姿势 |
| 入场镜头震动 | 幅度 `(2, 6)`、时长 `0.2` 游戏秒、频率 `20` | 每个有效落脚事件播放；零幅度或零时长关闭震动但保留声音 |

破损外观由根脚本监听 `signal_hp_loss`，致死伤害同样更新最终外观。场地选择读取实际包含本实例的关卡 `game_sences`；前院、后院、屋顶分别使用对应资源，缺省场地回退屋顶，屋顶资源也缺失时报告错误。

## 4. 状态流程、受击窗口与技能选择

普通流程为 `Enter → Idle → 完整技能 → Idle`；逻辑死亡可从任意行动阶段切入 `Dying → Dead`。子状态机由复合技能统一推进，不独立重复驱动。

| 完整技能 | 内部阶段 | 受击规则 |
| --- | --- | --- |
| `Spawn` | Prepare → Place → Interval → Prepare… → Finish | 关闭角色受击 |
| `HeadSkill` | Prepare → LowerHead → BeforeSpitIdle → SpitBall → AfterSpitIdle → RaiseHead | 由低头、抬头动画关键帧开启和关闭窗口 |
| `Bungee` | Prepare → Enter → Wait → Leave → Finish | 关闭角色受击 |
| `ThrowRV` | Prepare → Execute → Finish | 关闭角色受击 |
| `Stomp` | Prepare → Execute → Finish | 关闭角色受击 |

低头技能进入时不会立即开放受击。当前 `Zombie_boss_head_enter` 动画在 `2` 动作秒发送 `hurt_enable`；窗口保持到抬头动画 `Zombie_boss_head_leave` 的 `0.6667` 动作秒发送 `hurt_disable`。吐球前低头待机为 `1` 动作秒，吐球后当前场景为 `2` 动作秒。状态退出、死亡中断也会整理受击开关并通知检测器。

技能选择权重当前为 `Spawn = 3`，`HeadSkill / Bungee / ThrowRV / Stomp = 1`。实际选择顺序为吐球保底、初始序列、加权随机；初始序列不可用项跳过，吐球保底插队保留尚未执行的初始项。随机池有多个候选且抽中上次技能时，移除该技能后重新抽取；只有一个可用技能时允许连续。零权重只排除正常随机抽取，不能关闭初始序列或吐球保底。

一次完整放置技能无论放几只僵尸，都只累计一个技能回合。当前没有可用技能时重新待机，不累计空回合。主状态机的 `request_death()` 优先于普通状态请求，死亡后不再释放新技能动作。

## 5. 五种技能

### 5.1 放置僵尸 `SpawnSkill`

实现见 [z_b_001_doctor_skill_spawn.gd](../scripts/character/zombie_boss/001_doctor/skills/z_b_001_doctor_skill_spawn.gd)。每轮计划放置 `3～5` 只，放置间隔 `1` 动作秒，首只之前和末只之后不额外等待该间隔。每次选择合法行、普通僵尸类型及对应动作，通过手部标记点生成。

当前博士场景覆盖的僵尸池为 `[1, 3, 4, 5, 6, 7, 8]`。脚本默认池与当前场景池不同，调试时应以场景导出覆盖为准；候选的基础权重和战力来自角色注册表。

| 类型 | 基础权重 | 单只战力 | 可进后院水行 |
| --- | --- | --- | --- |
| 普僵 `Z001Norm` | `4000` | `1` | 是 |
| 路障 `Z003Cone` | `4000` | `2` | 是 |
| 撑杆 `Z004PoleVaulter` | `2000` | `2` | 否 |
| 铁桶 `Z005Bucket` | `3000` | `4` | 是 |
| 读报 `Z006Paper` | `1000` | `2` | 否 |
| 铁门 `Z007ScreenDoor` | `3500` | `4` | 否 |
| 橄榄球 `Z008Football` | `2000` | `7` | 否 |

放置使用整轮战力预算：原始初始预算 `4`，每成功准备三轮增加 `3`，原始上限 `100`。有效初始预算与上限会按「合法候选最低单只战力 × 本批数量」向上修正，在该博士实例内只升不降。本批预算按准备前次数计算，清单成功准备后再增加次数，死亡中断不回退。每次选型为余下名额保留最低战力，未用完预算不结转。

普僵、路障前六次准备使用基础权重；后续令 `d = clamp(准备前次数 - 5, 0, 20)`，普僵权重减 `180d`，路障减 `150d`，其余类型不按此规则衰减。脚本还支持配置雪橇的冰道检查及准备时替换冰车，但当前场景池不包含这两类。

后院水行只使用注册为水陆两用的类型；当前普僵、路障、铁桶可进水行，保留原类型并由普通僵尸初始化切换泳圈外观，其余四类限制为陆行。技能生成的普通僵尸计入场上敌人，标记为不参与自然波次提前刷新。

### 5.2 冰火球 `IceFireBallSkill`

实现见 [z_b_001_doctor_skill_ice_fire_ball.gd](../scripts/character/zombie_boss/001_doctor/skills/z_b_001_doctor_skill_ice_fire_ball.gd)。在完整低头流程中等权选择有效行，冰球、火球权重各 `1`；当前配置各占一半。准备时锁定行与类型，不按植物数量加权，释放时读取嘴部 X，每轮只吐一个球。

球体是独立道具实体，挂到关卡 `Items`，使用 [z_b_001_doctor_ball_base.gd](../scripts/character/zombie_boss/001_doctor/objects/z_b_001_doctor_ball_base.gd) 及冰、火子类；它不是普通追踪子弹或普通僵尸，不增加敌方僵尸数量。生成后由自身移动和碰撞流程负责生命周期，博士死亡不会自动删除已经生成的球。

当前球体场景沿用脚本移动参数：向左 `20 px/s`，滚动动画倍率 `0.1`，`X <= -300` 后移除。两种球成形动画均为 `1.25` 秒、成形倍率 `1`；成形期间不移动、不攻击、不发射地面轨迹。成形绝对 Z 为 `4001`，滚动后球 Z 为 `(lane + 1) × 50`，轨迹 Z 为 `lane × 50`。

根节点代表落地点，Y 根据所属行基准与当前位置屋顶坡面计算；生成后不跟随博士的移动或速度控制。碰撞植物真实受击区域和小推车：同行有效植物被命中后，其整个格子符合资格的各层植物执行 `be_flattened()`，不是固定 HP 扣血；同行小推车无须启动也可被压毁，球继续滚动。该伤害不会把球当角色攻击者触发地刺反击。

| 球类型 | 消除条件 | 边界 |
| --- | --- | --- |
| 冰球 | 同行火爆辣椒的 `jalapeno_bomb_item_lane` 事件 | 其他行辣椒不消球 |
| 火球 | 寒冰菇的全场 `ice_all_zombie` 事件 | 不限制行，也不使用冻结持续时间 |

消除对成形和滚动阶段都生效，但不补处理生成前事件；冰球与火球之间没有自动碰撞互消。释放或卸载会解除事件订阅；移除时停止轨迹发射，已有地面粒子继续消散。

### 5.3 蹦极偷植物 `BungeeSkill`

实现见 [z_b_001_doctor_skill_bungee.gd](../scripts/character/zombie_boss/001_doctor/skills/z_b_001_doctor_skill_bungee.gd)。默认随机选择完整连续三列，起始列范围为 `1～3`，对应 `123 / 234 / 345` 三组。每列筛选实际可偷取的植物，空列不从其它列补名额；手部 Y 不随植物行号变化。

有目标的完整列组等权抽取，每列等权锁定一格，实际蹦极偷取一层植物，优先级为 `Norm → Shell → Down → Float`。动作释放时经管理器创建实际蹦极僵尸，使用左、中、右三个手指定位点，空列不使后续手指槽位前移；目标仍受蹦极水陆资格限制。

Wait 保持进入动作末帧，等本批全部死亡或偷取结束再进入 Leave，没有超时计时器；零只成功创建则直接完成。已生成的僵尸由自己的生命周期处理，不因博士技能中断而直接删除。

### 5.4 砸车 `ThrowRVSkill`

实现见 [z_b_001_doctor_skill_throw_rv.gd](../scripts/character/zombie_boss/001_doctor/skills/z_b_001_doctor_skill_throw_rv.gd)。从场地配置允许的左上角中等权选择可容纳完整区域的位置，当前上限为行 `1～4`、列 `1～3`，覆盖 `2 行 × 3 列`；后院也沿用该上限。有无植物不影响概率，准备阶段锁定格子，落地关键帧读取最新植物并碾压各层，不按每帧持续伤害。

### 5.5 脚踩 `StompSkill`

实现见 [z_b_001_doctor_skill_stomp.gd](../scripts/character/zombie_boss/001_doctor/skills/z_b_001_doctor_skill_stomp.gd)。从完整且有存活出战植物的踩踏区域中等权选取，植物数量不改变概率。准备时若原有目标已全部消失，则允许从完整区域随机踩空；落地时再读取锁定格子中的实际植物。动作绑定动画、对应腿部位置和固定 `2 行 × 3 列` 区域；动作 `1 / 2` 使用内侧腿，`3 / 4` 使用外侧腿。

脚踩与砸车共用区域碾压逻辑。区域查询及植物去重由公共工具负责，双格植物或多个检测对象不能因此在同次释放中重复结算。

### 6.1 场地资源

| 前院 | [front_skill_config.tres](../resources/zombie_boss/001_doctor/z_b_001_doctor_front_skill_config.tres) | 放置与吐球 5 行；脚踩左上角行 1～4、列 7，覆盖列 7～9 |

资源中的行列从 `1` 开始，运行时普通僵尸行索引从 `0` 开始。行动作绑定 `animation_name` 和部件本地位置；踩踏动作还绑定完整格子区域。砸车范围必须能容纳完整大小，蹦极列组必须完整，地图边缘不会裁剪成较小攻击区。

`spawn_part_motion`、`ice_fire_ball_part_motion`、`stomp_part_motion` 分别配置定位和复位。`ZB001DoctorPartMotionConfig` 默认定位 `0.3`、复位 `0.2` 动作秒，曲线为 `TRANS_SINE / EASE_IN_OUT`；资源可覆盖，`0` 表示立即定位或复位。修改表现位置应调整相应部件或场地资源，根节点位置及受击框不会跟随每次吐球选行平移。

### 6.2 动画方法轨道协议

协议定义见 [z_b_001_doctor_animation_events.gd](../scripts/character/zombie_boss/001_doctor/data/z_b_001_doctor_animation_events.gd)。技能轨道调用 `StateMachine.notify_skill_event(animation_name, event_name)`；主层状态轨道调用 `StateMachine.notify_animation_event(event_name)`；奖杯轨道调用动画根节点的 `request_trophy()`。

| 动作 | 当前关键帧，单位为动画动作秒 |
| --- | --- |
| 放置 | `0`：`position_move`；`0.75`：`spawn_release`；`1.25`：`position_return` |
| 吐球攻击 | `0`：`position_move`；`1.25`：`ball_release`；`2.5`：`position_return` |
| 脚踩 | `0`：`position_move`；`1.5`：`stomp_impact` 与 `position_return` |
| 蹦极进入 | `1`：`bungee_release` |
| 砸车 | 约 `2.166667`：`rv_release` |
| 低头 / 抬头 | 低头 `2`：`hurt_enable`；抬头 `0.6667`：`hurt_disable` |

技能基类记录本轮已准备的动画及动作释放标记，同一动作只释放一次。调用必须匹配当前活动技能、动画名和事件名，旧动作迟到回调不能再次生成或伤害。配置校验检查轨道目标、方法、参数、有效时刻及动画循环要求；仅有同名事件但目标路径错误不能通过。

动画、部件平移和动作计时跟随博士实际动画倍率；`SpeedTimer` 保留基础动作时间，零速度时暂停推进。音效保持正常播放速度。控制器只调整本实例使用的动画副本，避免多只博士修改共享动画的循环设置。

部件父节点的局部 `position` 由平移控制器独占，不能同时被动画位置轨道写入；子精灵的姿势轨道仍可播放。Tween 使用物理更新和绑定暂停，动作计时器使用单次、物理更新且继承暂停的 `SpeedTimer`；全局时间倍率由引擎处理，不在调用方重复乘算。

## 7. 博士死亡演出

逻辑死亡与表现结束分开：HP 到死亡阈值时立即计为击杀，演出仍可继续。死亡请求停止行动计时和新技能释放，清理受击及控制效果；从低头阶段死亡时先完成必要抬头和部件复位，再进入机甲死亡动作。

机甲与驾驶员使用各自播放器，由死亡状态和动画控制器协调。当前机甲死亡动画总长约 `8.833333` 动作秒，在 `1.5` 动作秒以 `driver_death` 事件启动驾驶员死亡，在 `8.8` 动作秒请求奖杯。驾驶员死亡动作 `5` 动作秒，随后举旗一次约 `0.764706` 动作秒，再进入 `Dead` 的举旗循环；不需要等待机甲动画结束。

`Dead` 只停止状态机物理推进，机甲动画的方法轨道继续运行。死亡爆炸表现的速度变化和机甲动画结束信号由根节点独立连接，即使主层进入 `Dead`，这些持续表现仍能接收通知。

死亡爆炸从当前可见、有效的 12 个机甲标记中随机选点，间隔 `0.18～0.35` 动作秒、缩放 `0.65～1.1`，最多 30 次；机甲死亡动作结束即停止新增，不能理解为每次固定生成 30 次。单个爆炸动画长 `0.65` 动作秒，只有表现、没有伤害；已生成特效随死亡倍率播放并自行消散。爆炸配置错误只关闭该表现，不阻断死亡和奖杯链路。

最终进入举旗循环后，`Dead` 调用 `start_death_remain()`：根节点 `DeathRemainTimer` 等待 10 游戏秒，之后调用基类 1 秒淡出。这个计时器不在状态机的行动计时器集合中，不受死亡动画 1.5 倍速缩短，但仍受场景暂停和全局时间倍率影响。

博士配置校验要求死亡动画具有有效的根节点 `request_trophy()` 方法关键帧、独立保留计时器和奖杯生成标记。奖杯请求发生在演出关键帧，不需要等尸体保留及淡出结束。调用 `character_death_disappear()` 则立即请求并释放，仍受管理器判胜规则约束。

调整保留时长、驾驶员动画时长或奖杯关键帧时，应确保角色不会在奖杯请求前被释放。当前 10 秒保留配置留有余量，初始化校验不检查这些时间之间的先后关系。

## 8. 自动出场、卡牌召唤与多僵王

### 8.1 关卡参数

| 字段 | 默认值 | 当前用途 |
| --- | --- | --- |
| `boss_type` | `ZombieBossType.Null` | 自动出场类型；空值关闭自动入口，不限制卡牌召唤 |
| `boss_spawn_wave` | `0` | 自动入口：`0` 为开战生成，正常波次 `1..max_wave` 为指定波次生成 |
| `boss_spawn_position` | `Vector2.ZERO` | `%ZombieBossRoot` 下本地坐标，自动及卡牌都使用该固定位置；负坐标允许，值必须有限 |
| `win_on_boss_death` | `false` | 开启额外 Boss 死亡胜利途径，与自动出场是否配置独立 |

当前自动配置校验仅在 `boss_type != Null` 时执行，要求单轮 `game_round == 1`、出怪模式为 `Null / Norm`、非罐子且非我是僵尸模式；无出怪模式还要求 `boss_spawn_wave == 0`。自动僵王不能配置到锤僵尸模式。校验不通过时 `init_para()` 返回失败。

自动 `create_boss()` 成功后只使用一次，卡牌召唤不占用该记录。开战自动生成后，正常出怪仍继续首波等待；指定波次在该波普通出怪后检查并登记自动僵王。`Null` 模式不启动自然波次，始终保留普通僵尸场外清理。

现有自动配置的单轮限制仍存在，不能据此推断卡牌僵王不支持多轮保存；卡牌实例已有独立存档支持。

### 8.2 卡牌与生成入口

博士卡身份当前为 `CardType.ZombieBoss + content_id = ZombieBossType.ZB001Doctor`，在普通僵尸候选页末尾显示。它按植物、普通僵尸同样的可用列表、选卡名额和 `can_choosed_card` 规则参与选择、取消、预选及上次选卡；不强制携带，不配置 `boss_spawn_mode`。

普通卡槽每次成功召唤扣 `10000` 阳光，冷却为 `0` 游戏秒（无冷却）。手持只创建静态预览，移入植物格子后在该格子的普通植物锚点显示透明度 `0.5` 的虚影；点击格子确认后在固定 Boss 出生点生成。无需格子为空或匹配水陆，柱子模式也只生成一只。失败不扣费用、不启动冷却。

`can_summon_boss(boss_type)` 检查正式战斗、有效根节点、有限出生点和可实例化注册场景，不限制出怪模式、轮数、罐子或我是僵尸模式，也不设置存活上限。`try_create_boss_from_card(boss_type)` 每次返回新实例；多只实例使用同一固定位置，可能重叠。

`CardManager.create_temp_card(reference, global_pos, exist_time)` 允许临时僵王卡，成功使用即释放，不扣阳光、不启动普通冷却。金币槽、传送带和种子雨目前仍拒绝僵王。卡牌和图鉴制作细节见 [卡牌说明文档](卡牌说明文档.md)。

### 8.3 登记与计数

实际实例化共用 `_create_boss_instance()`，要求根节点继承 `ZB000Base`、具有 `%HpComponent` 和正数最大血量，且不能预设死亡。入树前设置初始化类型和本地位置，`register_boss()` 用实例 ID、弱引用和注册类型接线并计数。

僵王加入 `curr_zombie_num`，但不加入普通僵尸的行集合或自然提前刷新数量；博士生成的普通僵尸、蹦极也不阻塞自然提前刷新，仍计入普通敌方数量。`get_living_bosses()` 返回按登记顺序的存活快照，死亡演出节点仍可保留登记，但不属于存活列表。

## 9. 胜利条件、奖杯与轮间处理

`win_on_boss_death` 是额外 OR 条件。至少成功生成一只僵王，且累计确认死亡数等于累计成功生成数时，可提前结束本轮；未发生的未来自动生成不计入当前条件，直接删除实例不算击杀。

原有普通清场、罐子、脑子胜利与非末轮末波 49 秒推进规则始终有效。僵王死亡回调先检查普通清场，同次死亡若使末波敌方数量归零，普通清场先取得结算权，沿用即时结算；仅实际由额外 Boss 条件结束时才等待最后触发实例的奖杯请求。

额外 Boss 条件取得结算权后，将游戏阶段设为 `GAME_OVER`，停止自然及锤僵尸波次和轮间计时，不暂停场景树，死亡演出继续。`Null` 模式场外清理继续执行。普通僵尸此时仍可能进房导致失败，失败暂停因素会拦截迟到奖杯请求及奖杯点击回调。

结算链为 `request_trophy() → ZombieManager._on_boss_trophy_requested() → MainGameManager.complete_boss_victory() → _finish_round_victory()`。每轮通过 `try_claim_round_end()` 只接受一次结束请求；未末轮进入下一轮，末轮生成唯一奖杯。

轮间等待 3 游戏秒后保存，再进入查看僵尸和重选卡流程，正式开战重置结算记录。实际由 Boss 提前结束的正常波次跳过本轮剩余波次，并将存档波号标准化到本轮末波；只开启额外条件而由其他途径结束时，保留原波次规则。

普通多轮保留存活僵王及累计生成、死亡数；我是僵尸模式换轮移除僵王并重置统计，清场不算击杀。自动配置仍受单轮校验约束，不能直接以自动参数构造多轮 Boss 关卡。

### 战斗音乐

正式战斗时，[MainGameManager.refresh_battle_bgm()](../scripts/manager/main_game_manager.gd) 按存活僵王集合选择曲目：存在存活僵王就播放 `GameBGM.Boss`（`boss.mp3`），并保留关卡原有 `game_BGM` 配置。[SoundManager.play_bgm_if_changed()](../scripts/autoload/sound_manager.gd) 在同一曲目正在播放时保留进度，因此再次召唤僵王不会重播音乐。

最后一只存活僵王逻辑死亡或直接移除后，若仍需继续正式战斗，则恢复关卡原曲并从头播放；原曲本身就是 Boss 曲时，同曲目规则仍保持进度，无需等待死亡演出或节点释放。单轮启用 `win_on_boss_death`、全部已成功召唤的僵王均确认死亡并获胜时，先判胜再通知音乐更新，结算阶段保留 Boss 曲；同次死亡由普通清场条件先取得胜利时也保留。

多轮关卡在最后一只僵王死亡时先恢复关卡原曲，再判断本轮胜利，包括末轮。轮间启用 `look_show_zombie` 时播放选卡曲，下一轮正式战斗再按剩余存活僵王选择音乐。选卡、准备、结算和场景退出期间，僵王通知不会覆盖其它界面的音乐。

读档在选卡阶段只缓存僵王数据，正式战斗恢复实例后重新按存活集合选曲。开战的延迟音乐刷新也使用同曲目检查，不会重播读档恢复或卡牌召唤已切换的 Boss 曲。

## 10. 血条、存档与恢复

### 10.1 血条

关卡基础场景提供独立 `%ZombieBossRoot`，`z_index = 4000`。UI 由 [level_info.gd](../scripts/main_game_item/level_info.gd) 和 [ui_boss_hp_progress_bar.gd](../scripts/ui/main_game_ui/ui_boss_hp_progress_bar.gd) 管理。

有存活僵王时隐藏普通波次容器，显示最新登记且仍存活的一只，同时显示 `僵王 × N`。显示的是该实例已损失血量比例，满血为 `0%`、死亡为 `100%`，不是多只合计血量。显示对象死亡后切换到最新剩余实例；其它实例死亡只更新数量。

无存活僵王且非 `Null` 的正式战斗继续时恢复普通波次显示；实际 Boss 胜利等待或完成期间保留 `100%` 与 `僵王 × 0`。正常扣血过渡为 `0.2` 游戏秒，首次绑定和死亡立即同步；解绑时清理信号和 Tween。

### 10.2 轮末快照

[ResourceSaveGameMainGame](../scripts/resources/save_game/save_game_main_game.gd) 的 `boss_manager_data` 保存以下结构：

```text
living_bosses: 每只存活僵王的 boss_type、hp、position（根节点本地坐标）、is_auto
spawn_total: 累计成功生成数
dead_total: 累计确认死亡数
auto_spawned: 自动入口是否已成功使用
```

仅保存存活角色，不保存运行时实例 ID、技能阶段、技能剩余等待、成长预算、冻结状态或死亡演出进度。旧存档缺失该字段按空数据恢复。选卡阶段只缓存数据，正式进入战斗后、启用出战卡片前重新创建实例并恢复 HP，分配新 ID，从完整入场动作和初始技能序列开始。

恢复不再次增加累计生成数。零血量条目不恢复，超过最大值的 HP 限制到最大值；创建失败会报告错误。关卡过程存档仍是轮末快照，上次选卡由全局存档单独保存；当前卡槽快照不保存冷却或临时卡生命周期。

| 技能触发时刻或受击窗口 | 动画方法轨道 | 目标路径、方法参数、事件名与配置校验 |
| 机甲/驾驶员过渡和部件复位 | 动画控制器、部件控制器、平移配置 | 实例动画隔离、速度和死亡中断 |
| 博士卡费用与冷却 | `CharacterRegistry.ZombieBossInfo` | 普通卡结算、临时卡免费规则 |
| 自动出场或固定出生点 | `ResourceLevelData` | 自动参数校验和本地坐标语义 |
| 胜利与下一轮规则 | 两个游戏管理器 | 普通条件优先、本轮唯一结束请求、失败与存档 |

新增僵王时，应保留现有枚举编号，在 `ZombieBossType` 和 `ZombieBossInfo` 中追加类型、名称、场景、费用与冷却；制作继承 `ZB000Base` 的场景和实际行为，在状态改变时通知检测器，死亡时沿用逻辑死亡与奖杯请求协议。

需要可选卡和图鉴时，还须补源卡静态预览、可用僵王列表及图鉴资料。死亡动画必须能够发送奖励请求，强制退场应明确选择击杀接口还是纯清场；不要用普通僵尸行集合管理僵王，也不要直接操作全局胜利绕过统一结算入口。
