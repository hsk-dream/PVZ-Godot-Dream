# 卡牌说明文档

本文说明卡牌身份、源模板注册、创建接口、关卡配置、僵王出战与图鉴、选卡存档。其他开发约定见 [开发相关文档](开发相关.md)。

卡牌源模板集中在 `scenes/autoload/all_cards.tscn`，自动加载单例名为 `AllCards`。通用卡牌场景为 `scenes/ui/all_cards/card.tscn`。界面卡片、静态缩略图和实际角色实例分别创建；复制卡片不会创建出战角色。

## 卡牌身份

`CardBase.card_reference` 是唯一身份字段，类型为 `ResourceCardReference`，脚本位于 `scripts/resources/card/card_reference.gd`。身份与点击用途分开配置。

| 引用字段 | 用途与约束 |
| --- | --- |
| `card_type` | `CardType` 内容类别：`Null = 0`、`Plant = 1`、`Zombie = 2`、`ZombieBoss = 3`；新增类别时保留已有编号 |
| `content_id` | 当前类别对应的角色枚举值；植物使用 `CharacterRegistry.PlantType`，普通僵尸使用 `ZombieType`，僵王使用 `ZombieBossType`；`0` 表示未配置 |
| `is_imitater` | 模仿植物修饰，默认 `false`；设为 `true` 时，编号仍指向被模仿植物，不能指向 `P999Imitater` 或其他类别 |

编辑器中先选择 `card_type`，再选择 `content_id`；切换类别会把编号清为 `0`，切换到非植物类别也会清除模仿修饰。角色编号下拉选项随类别变化，不根据节点名称或所属容器推断身份。

模板索引使用 `(card_type, content_id)`；选卡索引使用 `(card_type, content_id, is_imitater)`，因此普通植物和对应模仿卡共用模板，但属于不同选卡项。`is_valid()` 检查枚举编号和修饰组合，是否已有模板另由 `AllCards.get_template()` 检查。

模板和关卡中的引用按只读使用。创建引用使用 `ResourceCardReference.create(type, id, imitater)`，需要独立副本时使用 `copy_reference()`，避免修改共享资源，也避免依赖 Resource 属性复制顺序。

## 制作与注册源卡牌

1. 在 `scripts/autoload/global/character_registry.gd` 中定义对应角色枚举和角色资料，提供角色名称、场景、费用、冷却等各自参数。
2. 在 `all_cards.tscn` 的源目录中添加通用 `Card` 实例，并为 `card_reference` 新建引用资源。植物目录为 `PlantCards`、`PlantCards2`，普通僵尸目录为 `ZombieCards`、`ZombieCards2`，僵王目录为 `BossCards`。
3. 设置引用类别、角色编号，源模板的 `is_imitater` 保持 `false`。同一类别和编号只注册一次；非法引用、模仿变体源卡和重复身份会报错，不会覆盖已有模板。
4. 在卡片的 `CardBg/CharacterStatic` 下制作静态角色节点树，调整位置、缩放和可见部件。这里只保留预览所需的图像节点，不挂载角色战斗脚本或启动技能。

`AllCards` 在运行时遍历上述容器的直接 `Card` 子节点注册模板。没有引用的卡片可以保留为布局占位；分类顺序由源容器顺序及子节点顺序决定，不再配置单独的卡牌位置编号。单纯添加一个新容器不会自动加入注册，需同步更新 `all_cards.gd` 的 `_source_directories`。

普通备选页按 `GlobalGameState.curr_plant`、`curr_zombie` 和 `curr_zombie_boss` 筛选可见角色；僵王追加在僵尸候选页末尾，博士默认可选。新增角色时需同步相应的可用角色列表。植物图鉴同样使用 `curr_plant` 中的角色，并要求对应图鉴资料存在。

费用、冷却和植物种植条件在 `CardBase._ready()` 中读取角色注册表，不在源卡中重复配置。紫卡背景由种植条件推导，模仿卡使用灰色背景及模仿材质；模式需要免费或无冷却时，在卡片入树并完成初始化后覆盖实例参数。

`P999Imitater` 是独立的模仿者选卡入口，不作为常规出战模板注册。实际选中的模仿卡引用为 `Plant + 被模仿植物编号 + is_imitater = true`。

## 创建接口与点击用途

| `AllCards` 接口 | 返回值与用途 |
| --- | --- |
| `get_template(reference)` | 查询只读源 `Card`；非法或未注册身份返回 `null` |
| `create_card(reference, context)` | 创建持有独立引用的 `Card`，返回时尚未入树；默认用途为 `Catalog`，非法身份或不支持的出战用途返回 `null` |
| `create_static_preview(reference)` | 复制源卡的 `CharacterStatic`，返回独立 `Node2D`；模仿引用应用模仿材质，非法或未注册身份返回 `null` |
| `get_references(card_type)` | 按源目录顺序返回该类别的独立引用列表 |
| `is_battle_card(reference)` | 判断是否为已注册的可出战植物、普通僵尸或僵王；模仿者选择入口不允许直接出战 |

`Card.CardContext` 在卡片入树前设置：

| 用途 | 点击行为 |
| --- | --- |
| `Catalog` | 源目录用途，不处理点击 |
| `Selection` | 选卡或取消选择，发送 `signal_card_click(card: Card)`；仅接收可出战卡 |
| `Battle` | 检查游戏阶段及卡片可用性后交给手持管理器 |
| `Almanac` | 发送 `signal_card_click(card: Card)`，由图鉴页面打开详情 |

卡牌成功放置后发送 `signal_card_use_end(card: Card)`，所属卡槽负责费用、冷却或卡片移除。连接上述信号时直接接收信号传入的卡片，不再额外绑定同一张卡。

备选卡占位使用 `scenes/ui/all_cards/card_candidate_container.tscn`，脚本类为 `CardCandidateContainer`。调用 `init_card_in_seed_chooser(card)` 后再将容器入树；容器保留背景、费用和独立静态预览，真实卡片选中后可以移到出战卡槽，容器不另存一份身份。

临时出战卡统一调用 `Global.main_game.card_manager.create_temp_card(reference, global_pos, exist_time)`，支持已注册的植物、普通僵尸和僵王，拒绝非法引用及未注册模板。位置为全局坐标；`exist_time` 默认 `-1.0`，负数表示永久存在，非负数为正常存在秒数，结束后另有 5 秒闪烁。到期时仍被手持的卡片等待退出手持再销毁。成功使用后卡片立即销毁，不扣阳光或启动普通卡槽冷却；取消手持或创建角色失败不消耗卡片，限时生命周期继续生效。临时僵王卡在正式战斗阶段于当前植物格子显示虚影，通过任意战场格子确认，沿用关卡固定出生点召唤。

## 关卡卡牌配置

`ResourceLevelData` 的卡片参数使用统一引用，不再分别组合植物和僵尸数组，也不补零：

| 字段 | 类型与规则 |
| --- | --- |
| `prechosen_cards` | `Array[ResourceCardReference]`；普通槽和金币槽按列表顺序创建预选卡，达到 `max_choosed_card_num` 后停止；普通槽的系统预选卡不能取消 |
| `conveyor_weights` | `Array[ResourceCardWeight]`；传送带随机权重池 |
| `conveyor_order` | `Dictionary[int, ResourceCardReference]`；传送带固定出卡表，键 `0` 为第一张、`1` 为第二张 |
| `seed_rain_weights` | `Array[ResourceCardWeight]`；种子雨独立的随机权重池 |
| `seed_rain_order` | `Dictionary[int, ResourceCardReference]`；种子雨固定出卡表，序号同样从 `0` 开始 |

`ResourceCardWeight` 位于 `scripts/resources/card/card_weight.gd`，每项包含 `card_reference` 和整数 `weight`，权重默认 `1`。只使用显式配置的条目：`0` 权重不参与抽取；负权重、空条目、僵王及非出战引用报错并跳过。有效条目的概率为其权重除以总有效权重，植物和普通僵尸在同一个池中抽取，不再先按类别分组。固定出卡表同样拒绝僵王。

固定出卡表优先于对应权重池，只有未配置的生成序号才随机抽取；计数在卡片成功创建后增加。非法固定项不会退回随机池，也不会推进序号。

传送带和种子雨配置相互独立。空池、全零或全部非法的池初始化时会报错，抽取返回 `null`，不会自动从目录补卡或使用默认卡。即使配置了固定序列，初始化仍会检查权重池；固定序列中的合法卡仍可生成，但遇到未配置的序号而池为空时，本次不生成且序号不前进。

## 僵王出战与图鉴

当前僵王源卡为 `all_cards.tscn` 的 `BossCards/Card1`，身份为 `ZombieBoss + CharacterRegistry.ZombieBossType.ZB001Doctor`。博士卡按植物、普通僵尸相同的普通选卡规则参与选择、取消、预选和上次选卡，占用一个选卡名额，并服从 `can_choosed_card`。不强制携带或预选博士。目录和图鉴隐藏费用、冷却遮罩及快捷键；选卡显示费用，出战显示费用、冷却和快捷键。

博士普通卡槽每次召唤消耗 50 阳光、冷却 7.5 游戏秒。点击卡片后进入手持预览，移入植物格子时在该格子的普通植物位置显示半透明虚影，点击任意战场格子确认；不检查格子占用、水陆或行号，也不执行柱子模式的同列复制。每次成功在 `%ZombieBossRoot` 下按关卡 `boss_spawn_position` 创建新的博士，沿用现有敌方战斗逻辑，不设置存活或累计召唤上限。普通卡槽只有新实例成功创建才扣费并进入冷却；临时卡成功使用后直接销毁，不扣费、不进入冷却。金币槽、传送带和种子雨入口仍拒绝僵王。

卡牌召唤不需要出场模式配置，与 `boss_type` / `boss_spawn_wave` 的自动出场独立；两种入口可以共存，自动入口仍只生成一次。`win_on_boss_death` 是额外胜利选项，原有普通清场、罐子、脑子胜利及多轮末波 49 秒计时规则始终有效；末轮计时器不创建奖杯。开启后，至少成功生成一只僵王且所有本局已生成僵王均确认死亡，也可提前结束本轮；尚未到达的自动出场波次不计入。

每轮只接受一次结束请求。同一次僵王死亡同时满足普通清场时，先按普通清场结算；仅实际由额外 Boss 条件结束时，停止刷新并接受最后一只的奖杯请求。正常死亡由死亡动画请求奖杯；调用 `character_death_disappear()` 则计为击杀并在释放前立即请求奖杯，跳过演出。仅调用 `queue_free()` 的清场仍不计为击杀。普通条件或轮间计时已经结束本轮后，后续僵王动画请求不再次结算；游戏失败后不发奖。

实际由 Boss 提前结束的自然波次会跳过本轮剩余波次，轮间存档按本轮末波保存，续关从下一轮继续；其他结束途径保留原有波次规则。旧存档沿用已保存波号，不根据僵王死亡统计推断结束原因。无出怪模式始终保留普通僵尸场外清理。

血条绑定最新生成的存活僵王，同时显示存活数量；显示实例死亡或离树后切换到最新剩余实例。普通多轮关卡保留存活僵王及累计生成/死亡数；我是僵尸模式沿用轮间清场规则移除僵王并重新累计。每轮奖杯请求独立防重入。寒冰菇和火爆辣椒的全场僵王效果逐实例处理，各实例仍自行检查受击窗口。

植物图鉴使用 `CardContext.Almanac` 的通用卡片；普通僵尸和僵王共用 `scenes/almanac/almanac_portrait_card.tscn`，脚本类为 `AlmanacPortraitCard`。头像通过 `create_static_preview()` 取得静态节点，点击发送 `signal_card_click(reference: ResourceCardReference)`；该信号与通用卡片传入的 `Card` 参数不同。

图鉴资料保存在 `data/almanac_data.json`，类别分组为 `Plant`、`Zombie`、`ZombieBoss`，条目键使用角色注册表中的名称。博士条目为 `ZombieBoss/ZB001Doctor`，常用字段包括 `名字`、`描述`、`参数`、`简介`、`背景`，可选提示字段为 `提示`；`背景` 使用详情面板支持的背景键，如 `Roof`。

僵尸图鉴先展示已解锁普通僵尸，再追加已注册且有资料的僵王。普通僵尸和僵王条目均要求有源模板及对应资料；新增僵王时需同时补齐角色注册表、源卡及 JSON 条目。

详情统一调用 `AlmanacCharacterShowPanel.show_card(reference)`，使用角色注册场景创建展示实例，并在入树前设置 `Character000Base.E_CharacterInitType.IsShow`。博士展示状态的机甲循环播放 `Zombie_boss_head_idle`，驾驶员播放 `Zombie_Boss_driver_idle`。缩略图构图在源卡及 `AlmanacPortraitCard` 中调整，详情模型构图在 `panel_container.gd` 的 `_apply_show_layout()` 中调整，避免修改战斗场景定位。

后续新增内容类别时，保留已有 `CardType` 编号，并同步扩充引用校验、编辑器角色选项、目录来源及对应展示逻辑。是否允许出战由 `is_battle_card()` 和实际放置入口明确实现，不能仅添加枚举就进入战斗。

## 选卡存档与关卡保存

全局存档由 `SaveService` 写入 `user://<用户名>/GlobalSaveGame.json`，保存金币、花园、关卡状态及上次选卡等数据。上次选卡的运行态为 `GlobalGameState.selected_cards: Array[ResourceCardReference]`，保存时保持卡槽顺序，将每个引用编码成以下 JSON 字典，不直接保存 Resource 对象：

```json
{"card_type": 1, "content_id": 1, "is_imitater": false}
```

`selected_cards` 是上述字典的数组，三字段均需存在；类别和角色编号需为有效的有限整数，模仿修饰需为布尔值。完整全局存档与 `save_selected_cards()` / `load_selected_cards()` 共用编码、解码逻辑，单独保存选卡只更新该字段，保留其他全局数据。

旧 `plant_type` / `zombie_type` 选卡格式不转换、不恢复，需要重新选卡；非法条目跳过，缺失或非数组列表恢复为空。重选时还会过滤不支持出战、本次候选页不存在或未解锁的内容，以及已有预选卡和重复模仿卡。

关卡过程存档使用 `ResourceSaveGameMainGame`，记录轮数、植物格子数据、僵尸波次、天降阳光生成量、卡槽数据和小推车数据；应从空白主游戏场景加载。可选字段 `boss_manager_data` 保存存活僵王的类型、血量、本地位置、累计生成/死亡数与自动出场记录；旧存档缺少该字段时按空数据处理。选卡期间仅缓存，正式战斗开始后恢复，从完整入场动作重新进入状态机，不还原技能或死亡动画中间状态。

当前 `CardManager` 的关卡存档只保存普通模式的阳光数量，不包含卡牌冷却、传送带队列或临时卡生命周期；博士卡同样遵循这一约定，上次选卡由上述全局存档单独维护。
