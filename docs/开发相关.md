# 项目目录说明
该部分解释说明本项目主体目录(二级目录未完全列出)
- addons:插件目录,主要使用RGa_PVZ和anim_player_refactor插件处理动画
- animation:动画目录,保存所有动画文件,大部分动画都是单独保存为tres格式文件,少部分保存在场景文件中
- assets: 资产文件夹,包含图片素材 音乐音效素材等,考虑到版权问题,<mark>github中将该目录删除,加群或者从大版本更新视频简介获取完整项目内容</mark>
- data: 主要保存Theme主题资源 和 数据文件(图鉴数据)
- docs: 文档目录,保存项目说明文档（如 [子弹说明文档](子弹说明文档.md)、[卡牌说明文档](卡牌说明文档.md)）
- readme_show: readme展示的相关图片资源
- resources: 资源文件夹
- - character_resouce: 角色相关资源文件夹:body掉血变化\植物种植条件 <mark>(植物种植条件资源必须保存在该目录下)</mark>
- - crazy_dave_resource: 戴夫对话资源
- - <mark>level_date_resource: 游戏关卡设置相关的资源文件</mark>
- scenes:场景文件
- scripts: 脚本文件
- - autoload: 自动加载的全局脚本文件
- - bullet: 子弹脚本文件
- - character: 角色脚本文件(僵尸\植物\组件)
- - resources: 自定义资源脚本文件(关卡\卡牌引用与权重\植物种植条件\戴夫对话\body变化)
- shaders: 着色器脚本文件
- shader_material: 材质文件,保存僵尸出土时材质设置

## 僵王博士脚本目录

博士专用脚本集中在 `scripts/character/zombie_boss/001_doctor/`，按职责划分子目录；外层仅保留所有僵王共用的基类。

```text
scripts/character/zombie_boss/
├── z_b_000_base.gd                  # 通用僵王基类
└── 001_doctor/
	├── z_b_001_doctor.gd            # 博士根节点：初始化、角色信号与死亡通知
	├── controllers/                # 动画控制与姿势过渡
	├── skills/                     # 技能执行逻辑、技能基类与区域碾压基类
	├── data/                       # 动画标识、动作配置和技能运行时数据
	├── objects/                    # 冰火球、地面轨迹及单次死亡爆炸特效
	└── utils/                      # 博士技能共用的格子查询工具

scripts/state_machine/zombie_boss/001_doctor/
├── z_b_001_doctor_state_machine.gd  # 主状态机与技能选择
├── z_b_001_doctor_state.gd          # 博士状态基类
├── z_b_001_doctor_skill_state.gd    # 技能状态基类
└── states/                         # 入场、待机、死亡及各技能的子状态
```

状态机脚本仍按角色放在独立的 `scripts/state_machine/` 目录；技能脚本负责实际效果，状态脚本负责动作流程。移动脚本时同步移动同名 `.gd.uid` 并保留其内容，更新场景等资源中的脚本路径。

死亡局部爆炸由 `ZB001DoctorStateDying` 调度，机甲死亡动画开始时启动，机甲动画结束时停止生成。标记挂在机甲精灵下，通过 `Dying` 的导出数组 `explosion_points` 手动绑定；每次从数组中全部有效且可见的位置随机选择一个。单次特效挂到博士根节点下的无脚本 `DeathExplosionEffects` 容器，并自行播放和释放。

`DeathExplosionIntervalTimer` 放在 `StateMachine/Dying` 下，使用 `SpeedTimer`；正常切入 `Dead` 后仍运行。博士根节点直接连接死亡状态的速度和机甲动画结束回调，爆炸不依赖当前活动状态的逐帧更新，也不等待本体举旗循环结束。

### 技能场地资源

博士场景根节点的 `skill_scene_configs` 字典绑定前院、后院、屋顶三个 `ZB001DoctorSceneConfig` 资源，保存在 `resources/zombie_boss/001_doctor/`。博士根据所属关卡的 `game_para.game_sences` 选择资源；没有活动关卡或对应资源未绑定时默认使用屋顶。主游戏场景和僵尸管理器不保存博士专属的配置引用。

`spawn_row_actions` 与 `ice_fire_ball_row_actions` 的键为从 1 开始的显示行号，每项同时保存动画和部件的绝对局部位置；允许多行使用同一动画。放置控制 `OuterArm`，吐球控制 `Head` 并同步根节点受击框的位置，脚踩控制 `OuterLeg`；动画继续控制这些父节点下的子精灵。

`stomp_actions` 每项配置动画、部件位置、攻击左上角和范围，范围默认 2 行 3 列。蹦极的连续列组默认覆盖 3 列，资源保存第 1 列的 `InnerArm` 基准位置和起始列范围；砸车保存第 1 行第 1 列的 `InnerArm` 基准位置、候选左上角范围及攻击大小。蹦极进入／离开、砸车动作均只有一个，动画名称使用 `ZB001DoctorAnimations` 常量，不重复导出。

屋顶资源迁移当前五个放置动画、五个吐球动画和四个脚踩区域，部件位置均为零。按当前格子布局换算，蹦极第 1 列基准为 `(-82.5, 0)`，砸车 `(1,1)` 基准为 `(-82.5, -85)`，保留原来的第 2 列和 `(2,2)` 动画定位效果。前院和后院资源以各自行位置及格子布局配置初始偏移，后院第 6 行复用第 5 个放置和吐球动画。

共享资源只读，运行时清单、权重和次数由各技能实例维护。技能正常结束恢复初始化保存的待机位置，放置间隔也会复位；低头死亡时先保留当前行的头部和受击框定位完成抬头，再恢复位置并播放机甲死亡。

# 植物僵尸动画
使用[R2Ga_PVZ](#r2ga_pvz)将植物大战僵尸的动画文件转换为Godot游戏引擎所支持的动画格式。

僵尸动画：
- 使用插件[anim_player_refactor](#anim_player_refactor)删除一些轨道，主要是删除删除僵尸胳膊和头相关的visible轨道，僵尸掉手或掉头时使用代码控制visible。
- 或者将需要使用代码隐藏的节点用一个新的Node2D节点作为其父节点，代码控制其显示与隐藏，不用修改动画文件（推荐）

植物动画：
- 植物射击时眨眼和idle时眨眼节点不同，由于射击时眨眼动画需要使用visible轨道，使用插件[anim_player_refactor](#anim_player_refactor)将idle时的眨眼节点visible轨道删除，使用代码控制植物眨眼。

## 子弹类型
子弹分为4类: 直线\抛物线\追踪子弹\ 其他（加农炮）
### 直线
直线型 非穿透性攻击 子弹在碰撞到屋顶斜坡时判断是否破碎

### 抛物线
抛物线子弹使用贝塞尔曲线控制子弹弹道,根据目标僵尸位置确定终点位置,可以跟随僵尸移动,僵尸移动超出一定限制,固定最终落点

### 追踪子弹
追踪子弹根据贝塞尔曲线每帧更新移动方向

### 加农炮子弹
加农炮子弹继承Node2D节点,与子弹基类无继承关系

# 碰撞相关

## 碰撞检测

### 斜面地图
角色受击碰撞箱分为两类: 检测受击碰撞箱和真实受击碰撞箱
非斜面(屋顶)地图:检测受击碰撞箱和真实受击碰撞箱重合
斜面(屋顶)地图:
- 定义两个层面: 真实层面 & 检测层面  (两个层面的位置在斜面上有不同)
- - 检测层面: 检测层面,为一个水平线,每一行的水平面,直线,受击检测框,攻击检测框,处于该层面,在斜面时,角色本体(根节点)根据斜面移动,检测层面所在组件移动回原始位置，
- - 真实层面: 地图斜面时角色本体(根)所在层面. 在斜面时,角色本体(根节点)根据斜面移动,子弹攻击敌人时,子弹检测真实碰撞箱
爆炸组件中，一般爆炸组件的检测框在检测层面，爆炸特效在真实层面，不移动


除了子弹检测目标\无行属性攻击组件直线子弹植物(杨桃)\小推车检测僵尸时使用真实层面的检测框,其余检测均使用检测层面检测框

### 检测过滤
检测碰撞时会同时检测角色受击状态
  若可以检测者可以检测到目标受击状态,发射可以攻击信号
  若不能攻击,连接僵尸状态改变信号,僵尸状态改变时,重新判断是否可以攻击

植物:
```gd
enum E_BeAttackStatusPlant{
	IsNorm = 1,		## 正常
	IsFloat = 2,	## 悬浮
	IsDown = 4, 	## 地刺
	IsShort = 8, 	## 低矮植物（僵尸方子弹检测过滤 没有做僵尸方直线子弹 未使用）
}
```
僵尸:
```
enum E_BeAttackStatusZombie{
	IsNorm = 1,		## 正常
	IsJump = 2,		## 跳跃
	IsDownPool = 4,		## 水下
	IsSky = 8,			## 空中
	IsDownGround = 16,	## 地下
	IsJumpInPool = 32,	## 跳入泳池,该状态无法被高建国拦截
}
```

## 碰撞层说明
- layer 1 World : 世界层，房子区域\泳池碰撞\屋顶斜坡
- layer 2 PlantHurtBoxDetecttion : 植物层，植物所在层
- layer 3 ZombieHurtBoxDetecttion : 僵尸层，僵尸本体所在层，
- layer 4 BulletFromPlant : 植物子弹所在层，
- layer 5 ZombieHurtBoxDetecttionOnAttack : 僵尸攻击碰撞时受击碰撞箱所在层,不攻击时和本体受击碰撞箱重叠,攻击时向前移动,特殊植物可以检测(倭瓜\大嘴花)
- layer 6 ZombieHurtBoxDetecttionBeHypnotized : 僵尸被魅惑层，被魅惑僵尸改变至该层，植物子弹检测不到，
- layer 7 Bowling : 保龄球子弹层，撑杆跳僵尸可以检测到该层跳跃，
- layer 8 BulletFromZombie : 僵尸子弹区域所在层,无用
- layer 9 PlantHurtBoxReal: 植物真实受击区域
- layer 10 ZombieHurtBoxReal: 僵尸真实受击区域
- layer 11 ZombieHurtBoxRealBeHypnotized: 魅惑僵尸真实受击区域
- layer 12 ItemDetect:道具检测层(梯子、脑子等)
- layer 13 ItemReal: 道具真实层
- layer 14 LawnMover: 小推车区域，现有 Area2D 的 `collision_layer` 为 `8192`，`monitoring` 和 `monitorable` 均开启；冰火球据此检测并碾压同行小推车。

# 主游戏 渲染层级相关

显示顺序先由 `CanvasLayer.layer` 决定，再在同一画布内按 `z_index` 排序，数值越大越靠前。不同画布之间不能通过提高 `z_index` 改变前后关系。

## CanvasLayer

以下以 `MainGame00Base.tscn` 为准；主游戏根节点下的植物、僵尸、僵王和道具使用默认画布层 `0`。

| 节点或画布 | `layer` | 显示内容与变化规则 |
| --- | --- | --- |
| `CanvasLayerBG` | -10 | 背景、房屋等背景对象 |
| `CanvasLayerCardSlot` | -1 / 10 | 选卡、准备阶段为 10，进入战斗后为 -1；开启鼠标焦点置顶时，鼠标进入卡槽切到 10，离开恢复 -1 |
| 默认画布 | 0 | 植物格子、僵尸行、小推车、子弹、僵王、冰火球、爆炸和阳光 |
| `CanvasLayerFG` | 5 | 浓雾等前景 |
| `CanvasLayerDropItem` | 6 | 金币、花园植物等奖励掉落 |
| `CanvasLayerCardSlotFront` | 10 | 卡槽前景容器 |
| `CanvasLayerTemp` | 20 | 临时种植角色、种植虚影和铲子 |
| `CanvasLayerEffect` | 30 | 寒冰菇、毁灭菇等全屏特效 |
| `CanvasLayerUI` | 50 | 提示、波次进度、僵王血条和菜单 |
| `CanvasLayerAlmanac` / `CanvasLayerConsole` | 60 | 图鉴和控制台 |

## 主游戏 z_index

行号 `lane` 从 `0` 开始，第一行为 `0`。按行显示的对象每向下一行增加 `50`；以下规则均用于默认画布。

| 对象 | 第一行或固定 `z_index` | 设置规则 |
| --- | --- | --- |
| 冰火球地面轨迹 | 0 | `lane * 50`，使用绝对层级 |
| 植物格子所在行 | 10 | `PlantCellManager` 设置为 `lane * 50 + 10`，植物继承所在行的层级 |
| `ZombieRow` | 30 | `ZombieManager` 初始化时设置为 `lane * 50 + 30` |
| 小推车 | 40 | 生成时设置为 `lane * 50 + 40` |
| 普通子弹 | 45 | `init_bullet()` 设置为 `lane * 50 + 45` |
| 冰火球移动阶段 | 50 | `(lane + 1) * 50`，使用绝对层级 |
| 追踪子弹、玉米加农炮炮弹、被保护伞弹开的抛物线子弹 | 4000 | 对应初始化或弹开逻辑设置固定层级 |
| 僵王机甲（`ZombieBossRoot`） | 4000 | 主场景固定设置，僵王子节点继承该层级，不按行递增 |
| 命中僵王的子弹特效 | 4001 | `BulletEffect000Base.BOSS_HIT_EFFECT_Z_INDEX`，使用绝对层级，显示在机甲前方 |
| 僵王死亡局部爆炸 | 4001 | 生成位置取机甲精灵下的 `Marker2DDeathExplosion*` 全局位置，单次特效使用绝对层级 |
| 冰火球成形阶段 | 4001 | 生成时设置绝对层级，成形完成后切换到对应行 |
| `Bombs` | 4001 | 爆炸容器的固定层级 |
| `Suns` | 4002 | 阳光容器的固定层级 |

普通子弹命中特效脱离子弹后，沿用原子弹的 `z_index` 和相对层级。普通目标的特效 X 对齐目标受击组件，Y 保持原值；命中僵王时保留特效在命中时的全局位置。普通溅射与火豌豆特效命中僵王后均切换到绝对层级 `4001`，致死命中也使用这一规则。它们挂到子弹原父节点并保留全局变换，独立播放至结束。

`z_as_relative = true` 时，节点的层级会叠加父节点的有效层级；`false` 时使用自身的绝对层级。因此僵王命中特效、冰火球和地面轨迹使用 `false`，避免重新挂载后叠加容器层级。同一 `z_index` 的对象仍按场景树绘制顺序排列，`4001` 内部没有额外的优先级约定。

每行植物格子的场景节点顺序为从右向左；`PlantCellManager` 获取节点时，将 `all_plant_cells` 更新为从左向右。

## 僵王冰火球挂载与位置

冰火球生成时直接挂载到主游戏的 `Items` 节点下，成形和移动阶段均保留该父节点。初始 X 取僵王嘴部生成标记的全局 X，初始 Y 取目标行僵尸生成点的全局 Y，并叠加该 X 处的屋顶斜坡修正。

成形阶段使用 `z_index = 4001`；变大动画完成后切换为对应行的移动层级。冰火球使用 `z_as_relative = false`，避免叠加 `Items` 的层级。

地面轨迹粒子初始挂在球下且不发射；成形完成后保留全局变换转挂到 `Items`，设置独立的按行层级并开始发射。球移除后，已发射的轨迹粒子继续存活至生命周期结束，再释放粒子节点。


# 植物种植相关
植物位置有四种: `float(漂浮植物:咖啡豆)、down(底部植物:花盆、睡莲)、norm(正常普通植物：豌豆射手)、shell(壳类植物：南瓜头)`
地形分为6种（植物格子为某一种类型+“无”类型）：`"1 无", "2 草地", "4 花盆", "8 水", "16 睡莲", "32 屋顶/裸地"`

植物种植的地形可以为多种，如豌豆射手：`22 = 2(草地) + 4(花盆)+ 16(睡莲)`
植物的位置属性只能选一种

## 植物种植条件
每个植物的种植条件使用自定义资源（`ResourcePlantCondition`），相同的种植条件可以使用同一个资源
种植条件资源需要保存在`res://resources/plant_resource/plant_condition/`目录下

植物种植条件分为特殊和非特殊,
紫卡植物一般为非特殊植物,
特殊植物需要重写对应资源脚本,重写特殊植物种植条件函数代码
特殊紫卡植物(玉米加农炮)判断是否能种植时,只走特殊植物判定种植函数,不会在走紫卡植物判定函数
双格植物只针对玉米加农炮写了个资源脚本,若扩展需写对应的资源脚本文件

## 植物格子
植物格子（`PlantCell类`）管理当前格子的植物
普通植物种植时需同时满足当前植物格子空闲位置和地形才可以种植
特殊植物需继承种植资源脚本重写判断函数判断是否可以种植

植物格子有每个位置对应的植物容器作为种植植物的父节点
原始PlantCell节点如下：
- PlantCell (PlantCell)
  - PlantDownContainer (Node2d)
  - PlantFloatContainer (Node2d)
  - PlantNormContainer (Node2d)
  - PlantShellContainer (Node2d)

本项目norm和shell位置的植物可以跟随down的植物上下移动（原版花盆种植植物后就不动了，我写完才发现，就这样了）
down位置植物需要容器节点（DownPlantSelfContainer）作为norm和shell位置植物的父节点，down位置植物移动容器节点从而带动norm和shell位置植物移动（使用动画或tween控制移动）
种植down位置植物时将植物格子的norm和shell位置的容器节点作为down位置植物的容器节点的子节点。
down位置植物节点如下：
- DownPlant(Plant)
	- DownPlantSelfContainer(Node2D)

# 角色（植物和僵尸）
角色（植物和僵尸）根节点只处理基础属性、动画、body相关以及部分特殊角色功能(简单\与角色本体高度耦合不好拆分的)(土豆类准备\大嘴花攻击\魅惑)，其余全都由组件(攻击\攻击检测\移动\睡眠等基础组件)完成
信号连接必须要在角色本体中连接,除非为依赖组件(攻击行为组件与攻击检测组件)


**角色`_ready()`函数中固定根据初始化类型不同进行不同的初始化，继承的植物和僵尸不重写`_ready()`函数，而是重写`init_norm()`函数进行初始化**

角色在`add_child()`添加到节点树之前,使用init_*()函数对角色相关参数(行\初始化类型等)赋值
创建僵尸统一使用ZombieManager的create_norm_zombie()函数创建
部分主游戏全局使用的数据(植物格子\僵尸行等)放在自动加载单例MainGameDate中,每次加载主游戏场景时由对应子管理器更新赋值


## 组件信号连接
为避免信号漫天飞的情况，规定角色及其组件信号连接必需遵循以下规则（角色类的信号）：
- 角色类本身的Timer节点的timeout信号可以在编辑器中直接连接信号，组件自身的Timer信号必须连接至该组件本体节点
- 组件自定义信号父节点可以连接子节点的信号，如：
  - 攻击组件（父） 攻击检测组件（子）
- 角色速度影响的组件，在角色根节点属性中添加该组件，在角色信号连接函数中连接信号
- 组件影响组件禁用相关的，在禁用发起组件（睡眠组件、胆小组件）中添加影响组件，在角色信号连接函数中连接信号
- 除上述情况以外，其余所有自定义信号都必须由角色本体在_ready()中对应的初始化函数中连接信号

__正常出战(Norm)角色死亡必须通过血量组件掉血死亡,禁止直接删除角色__


# 存档机制

全局存档由 `SaveService` 写入 `user://<用户名>/GlobalSaveGame.json`，保存金币、花园、关卡状态及上次选卡等数据。选卡身份的 JSON 结构与恢复规则见 [卡牌说明文档的选卡存档与关卡保存](卡牌说明文档.md#选卡存档与关卡保存)。

关卡过程存档使用 `ResourceSaveGameMainGame`，记录轮数、植物格子数据、僵尸波次、天降阳光生成量、卡槽数据和小推车数据；应从空白主游戏场景加载。卡牌状态的保存范围见上述卡牌文档。
